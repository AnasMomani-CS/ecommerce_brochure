Request → Response Flow

A user interaction on the mobile app triggers an HTTP request that flows through the API layers, services, and repositories to query or modify data in SQL Server, then returns a JSON response through the same layers back to the Flutter UI.

Engineering Practices

The project was built using solid software engineering principles that ensure maintainability, scalability, and reliability:

Separation of Concerns

Clear boundaries between presentation, business logic, data access, and database layers minimize coupling and improve testability.

Dependency Injection

Services and repositories are injected rather than hard-coded, improving flexibility and enabling easier unit testing.

Repository Pattern

Data access logic is abstracted into repositories, providing a clean API for querying and modifying data.

AutoMapper

DTOs (Data Transfer Objects) are automatically mapped between API contracts and domain models, reducing boilerplate.

Exception Handling & Logging

Comprehensive exception handling and structured logging enable quick debugging and production issue resolution.

Validation

Input validation at multiple layers prevents invalid data from reaching the database and ensures API contract compliance.

SDLC Principles

Software Development Life Cycle principles provide a structured approach to planning, designing, developing, testing, deploying, and maintaining software systems.

DRY (Don't Repeat Yourself)

Common logic is extracted into reusable services and utilities to reduce duplication and maintenance burden.

Code Organization

Projects are organized by concern (API, Application, Data, Infrastructure) with clear naming conventions and folder structure.

Security Architecture

The application implements security best practices to protect user data and API endpoints from unauthorized access.

JWT Authentication

User provides credentials
Server validates the credentials and generates a signed JWT token
JWT token is returned to the Flutter client
Client stores the token and sends it with protected API requests
.NET Core validates the JWT on each protected request
The authenticated user identity and claims are extracted from the token
Authorization determines whether access is allowed based on the authenticated user and required permissions

HTTPS Communication

Encrypted data in transit
Authenticates the server through TLS certificates
Protects data confidentiality and integrity
Helps prevent man-in-the-middle attacks
Secures communication between the client and API

Each API request is secured with JWT bearer tokens in the Authorization header. The server validates token authenticity and expiration before processing requests. HTTPS ensures encrypted communication between the Flutter app and the .NET Core API, protecting sensitive data from interception.

Database Architecture

SQL Server stores all application data with Entity Framework Core handling object-relational mapping and query execution.

Entity Framework Core

DbContext manages database access and entity tracking
LINQ queries are translated into SQL when supported by EF Core
Change tracking detects entity changes for updates
Database schema and relationships are mapped through EF Core configuration
Relationships are configured through entity navigation properties and EF Core mappings
Async CRUD operations are simplified through DbContext and repository abstractions

Entities & Relationships

Product — represents grocery items
Category — organizes products
Favorite — user saved items
Promotion — discounts & offers
Cart — current shopping items
Order — purchase history
User — account data

The repository pattern abstracts data access, allowing services to query and modify data without direct SQL knowledge. EF Core's lazy loading and eager loading strategies optimize query performance for mobile-friendly response times.
